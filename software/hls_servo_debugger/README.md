# HLS 舵机浏览器调试工具

这是一个面向飞特 HLS 系列串行总线舵机的浏览器调试软件，放在
`microduck-community-kit/software/hls_servo_debugger` 下。后端使用 Python + Flask + pyserial，
前端为纯 HTML/CSS/JavaScript，无需前端构建工具。

工具以 `FTServo_Linux-main/src/HLSCL.cpp`、`SCS.cpp` 和官方
《磁编码 HLS 舵机-内存表解析》为依据，覆盖 HLS 舵机的指令、内存表、控制模式、
同步读写和原始协议调试。

## 功能范围

- 串口连接：`/dev/ttyACM1` 等设备选择、常用波特率、超时设置、自动探测 ID1。
- **整机 15 台舵机初始化**：按 microduck 的关节表逐个把出厂舵机（ID 1）编号成
  20~24 / 30~34 / 10~14，并按选择的工艺做初始位置校准、回读校验和写入锁保护；
  15 台列表按 ID 升序显示，点检后在线的点黄、本页已完成的显示绿；
  另有 9/11 号多圈开关（默认关闭）、19 号电压/过流保护开关（默认关闭）。
  见下文《整机 15 台舵机初始化》。
- PING / 扫描：单个 Ping、按 ID 范围扫描、可读取版本。
- 实时反馈：一次读取 56~70 共 15 字节，显示位置/速度/负载/电压/温度/状态/移动/目标位置/电流，并绘制趋势图。
- 位置控制：位置伺服模式、扭矩开关、目标位置、速度、加速度、目标电流、转矩限制、角度限制、异步写（REG_WRITE）+ REG_ACTION、中位校准（可选 CAL 后保存到 EPROM 并重新上锁）。
- 速度/电流/PWM：恒速模式、恒流模式、PWM 开环模式，以及对应写入方法。
- 参数配置：按 HLS 内存表自动生成 0~86 字段的读取/写入界面，支持枚举、位域、正负号字段编码；
  回读值列只显示可读懂的结果（计数 + 工程量 / 枚举名 / 打开的位名），原始字节放在悬停提示里。
- 同步读写：SYNC_READ(0x82)、SYNC_WRITE(0x83)、同步位置写、同步速度写。
- 高级调试：任意地址/长度 READ/WRITE、REG_WRITE、REG_ACTION、RESET、RECOVERY、CAL、写锁控制、原始十六进制帧收发。
- 日志：显示 TX/RX/错误帧，便于核对校验和和异常。
- 内存表参考：完整字段、地址、范围、单位、方向位说明。

HLS 参考库中的 `WritePosEx`、`RegWritePosEx`、`SyncWritePosEx`、
`SyncWriteSpe`、`ServoMode`、`WheelMode`、`EleMode`、`WriteSpe`、
`WriteEle`、`EnableTorque`、`unLockEprom`、`LockEprom`、
`CalibrationOfs`、`FeedBack`、`ReadPos/ReadSpeed/...` 均有对应前端操作或
API 入口。

## 安装与运行

### 方式一：使用 `run.sh`

```bash
cd microduck-community-kit/software/hls_servo_debugger
./run.sh
```

脚本会自动用 `uv` 创建 `.venv` 并安装 Flask、pyserial，然后启动服务。

### 方式二：手动使用 uv

```bash
cd microduck-community-kit/software/hls_servo_debugger

uv venv .venv --python python3
uv pip install 'Flask>=2.2,<3.0' 'pyserial>=3.5'

uv python -m hls_debugger
```

启动后浏览器访问：

```text
http://127.0.0.1:8765/
```

默认会自动打开浏览器；使用 `--no-browser` 可禁止自动打开：

```bash
.venv/bin/python -m hls_debugger --no-browser --port 8765
```

### 方式三：直接跑在机器鸭核心板上（推荐，见下文《部署到核心板》）

核心板上没有 `uv`，依赖用 apt 装（`python3-flask` / `python3-serial`），
`run.sh` 会自动退回系统 Python，并把默认串口设成 `/dev/ttyS2`：

```bash
ssh root@<板子> 'cd /opt/hls_servo_debugger && ./run.sh --host 0.0.0.0'
```

然后在同一局域网的电脑上开 `http://<板子IP>:8765/`。

## 部署到核心板（radxa-zero3）

这块板子的事实（2026-10-05 实测）：`root@192.168.124.4`、Armbian 26.8.1（Ubuntu 26.04）、
**Python 3.14**、**没有 `uv` 也没有 `pip`**、apt 能连上 `ports.ubuntu.com`；
舵机与 `imu_to_dxl` 小板共用 **`/dev/ttyS2`**（`/etc/robot/robotd.toml` 的 `bus.port`），
平时由 `robotd` 持有。

```bash
# 1) 依赖：用发行版的包，不碰 pip（板子上没有，也没有 PyPI 直连）
ssh root@<板子> 'apt-get update && apt-get install -y python3-flask python3-serial'
ssh root@<板子> 'python3 -c "import flask, serial; print(flask.__version__, serial.__version__)"'

# 2) 拷源码（.venv 是本机的 x86_64 环境，不要拷）
rsync -av --delete --exclude '.venv' --exclude '__pycache__' \
      software/hls_servo_debugger/ root@<板子>:/opt/hls_servo_debugger/

# 3) 用的时候手动起（前台跑，Ctrl-C 就停；没有 systemd 单元，也别做成开机自启）
ssh root@<板子> 'systemctl stop robotd'                    # 让出总线
ssh root@<板子> 'cd /opt/hls_servo_debugger && ./run.sh --host 0.0.0.0 --no-browser'
#    浏览器开 http://192.168.124.4:8765/  →「连接与扫描」选 /dev/ttyS2、1 Mbps →「点检 15 台」
# 4) 用完了：Ctrl-C 停掉它，再把总线还给 robotd
ssh root@<板子> 'systemctl start robotd'
```

**它故意不做成系统服务。**这是台面/标定用的工具，用完就该关：它和 robotd 抢同一根串口，
常开着只会制造"两个进程互吃应答帧"的机会。想让它在你退出 SSH 后继续跑就用 `tmux`/`nohup`，
但记住用完要收掉。

几条要注意的：

* **停 `robotd` 不会切扭矩**，机器人保持当前姿态；但这时没有任何人在平衡，别在它站着的时候
  去拧关节。
* **一次只让一个进程持有串口。** `robotd` 的 `TIOCEXCL` **拦不住 root**（实测：两个 root 进程
  能同时打开 `/dev/ttyS2`），所以本工具在连接前会扫 `/proc/<pid>/fd`，发现别人占着就返回
  `409 port_busy` 并点名（`robotd (pid 975)`）。`fuser -v /dev/ttyS2` 也能看是谁拿着。
* `--host 0.0.0.0`：**任何能连到板子的人都能给舵机写寄存器**，只在可信任的局域网里开。
* 自检（不需要硬件，也不需要 robotd 停）：`ssh root@<板子> 'cd /opt/hls_servo_debugger && python3 -m hls_debugger.selftest'`
  ——板子上没有 Rust 源码，与 `feetech.rs` 对拍的那条用例会自动跳过。

## 快速上手

1. 给舵机接好电源和串口总线，确认设备确实是 `/dev/ttyACM1`（核心板上是 `/dev/ttyS2`）。
2. 打开页面，在“连接与扫描”中选择串口，波特率先选 `1000000`，点击“连接”。
3. 点击“Ping”确认 ID 1 是否在线。若失败，依次尝试 115200、500000、250000、57600、38400，或使用“自动探测 ID1”。
4. 点开“实时反馈”，点击“读取一次/开始轮询”，观察位置、速度、电压、温度、电流。
5. 点开“位置控制”，先“打开扭矩”，确认机械安全后写目标位置。
   初次测试建议：
   - 目标位置：`2048`（约 180°）或接近当前位置；
   - 速度：`60`（约 43.9 RPM）；
   - 加速度：`10~30`；
   - 目标电流：从 `200`（约 1.3 A）左右开始，根据负载调整。
6. 修改 ID、波特率、角度限制等 EPROM 参数前，建议先关闭扭矩，必要时关闭写入锁。
   修改 ID 后需要重新连接/扫描新 ID；修改波特率后需要重新连接新波特率。
7. 整机装配时，用“舵机初始化”页签给 15 台新舵机编号并做初始位置校准，见下一节。

## 整机 15 台舵机初始化

microduck 有 15 个关节，新舵机出厂都是 **ID 1 / 1 Mbps**，需要逐个改成对应的关节 ID。
“舵机初始化”页签把这套流程做成了向导：**一次接一个新舵机**，改完一颗拔下来换下一颗。

### 关节表（来自机器人软件，不是本工具自造的）

关节角零点在 **2048 计数**上、**方向 = −1**，与 `microduck_feetech` 的驱动层一致
（`duck-control/src/feetech.rs` 的 `POSITION_CENTER` / `POSITION_DIRECTION`）：

```text
关节角 = DIRECTION · (计数 − 2048) · 2π/4096        DIRECTION = −1（实测）
计数   = 2048 + DIRECTION · 关节角/0.0879°          都在 0..4095 内
```

位置字段是干净的 **0..4095**、没有负值、没有方向位。**方向是实测值，不是继承值**：
XL330 那一代是 `+1`，HD-1910-C001 在同样的舵盘安装下转向相反（2026-10-03 手转三个关节，
`microduck_feetech/docs/robot/joint-direction-check.md`）。所以下表给两个数：

- **关节角计数** = `DEFAULT_POSITION` 换算出来的角度（可负，left_hip_pitch = −299）；
- **舵机字段** = 要写进 42/56 号寄存器的值 = `2048 + 方向 × 关节角计数`
  （方向 −1 时 left_hip_pitch = **2347**，负角在字段里表现为 2048 **以上**的计数）。

> **2026-10-05 更正。** 本页与工具在 2026-10-03 方向翻转之前写的是 `rad = +(计数 − 2048)·…`、
> 「舵机字段 = 2048 + 关节角计数」，那一列**整列是镜像的**（left_hip_pitch 曾写 1749）。
> 照旧表把关节摆过去，15 个关节会全部对到镜像位置；`POSITION_DIRECTION` 现在是唯一的
> 符号来源，`hls_debugger/selftest.py` 有一条用例直接读 `feetech.rs` 核对它。

| 部位 | 关节名 | ID | home 姿态 | 关节角计数 | 舵机字段（2048 − 角） |
|---|---|---|---|---|---|
| 左腿 | left_hip_yaw | 20 | 0.000° | 0 | **2048** |
| 左腿 | left_hip_roll | 21 | −5.002° | −57 | **2105** |

> 2048 是**关节角 0**，不是 home 姿态。两者相差上表两列之差：例如 left_hip_pitch 站在 home
> 姿态时读数应该是 **2347**，而"关节角 0"读 2048。整机装舵盘时别把这两个混起来。

这张表抄自 `microduck_feetech`（官方 microduck 的飞特舵机适配版）：

- `duck-control/src/model.rs`：`JOINT_IDS`（15 个总线 ID）、`DEFAULT_POSITION`（home 姿态角）、
  `FACTORY_ID = 1`、`EXPECTED_BAUD_CODE = 0`、`IMU_DXL_ID = 200`；
- `duck-ipc-proto/src/lib.rs`：`JOINT_NAMES`（关节名，顺序与 ID 表一一对应）。

`model.rs` 里那几条常量顺带钉死了本工具依赖的两个前提：**ID 1 与 200 都不属于任何关节**，
所以“总线上出现 ID 1”就等于“有一颗还没编号的新舵机”；新舵机出厂就在 1 Mbps，
不需要换波特率去找它。`selftest.py` 里有一条用例把这张表与 model.rs 的期望值逐项对齐，
改动机器人软件时它会先失败，而不是让工具悄悄用错表。

### 初始化一台舵机做了什么

1. **预检**：ID 1 必须在线；目标 ID 必须没有应答（已在线的关节会被拒绝，避免重复 ID）；
   顺便报告总线上还有哪些关节、有没有 IMU 节点。
2. **关闭扭矩**（40 号 = 0），厂商的 `unLockEprom()` 也是这个顺序。
3. **关闭写入锁**（55 号写 0，EPROM 写入掉电保存）→ **写主 ID**（5 号）→ 写完后
   舵机就开始用新 ID 应答，所以上锁也要发给新 ID。
4. **写波特率**（6 号 = 0，1 Mbps）与**应答状态级别**（8 号 = 1，保证后续指令都有应答）。
5. **9/11 号角度限制**：勾选「打开多圈绝对位置控制」写 **0/0**（多圈，取消固件行程限制），
   不勾选写 **0/4095**（单圈行程）。这个开关**两个方向都会真的写寄存器**——
   「关闭」是把 0/4095 写回去，不是跳过不写，所以对一台已经开过多圈的舵机同样有效。
   **界面默认关闭**（台面单机调试一圈内更安全）；整机装配必须打开，见下面《真机实测》。
6. **19 号卸载条件**（EPROM 位域，见 `memory_table.PROTECT_BITS`）：BIT0 电压保护、
   BIT1 磁编码、BIT2 过热、BIT3 过流保护，置 1 表示**触发时舵机卸载**（不再输出扭矩）。
   界面上有两个选项（电压 / 过流），**默认都不打开**——关节中途卸力就是摔倒，
   这个取舍交给人来定。工具按**读改写**只动 BIT0/BIT3，BIT1/BIT2 保持舵机原值。
7. **写位置环增益**：EEPROM **21/22**（掉电保存，上电加载进 RAM）与 RAM **50/51**
   （立即生效）。默认 **Kp = 32、Kd = 0**，两个都能在界面上改。
   **不要用 `robotd` 那份默认的 200**：那是给 XL330 的 0..16383 标度调的，在飞特
   0..254 上是顶格，实测会让关节自激振荡（5 A、74 °C）。`Kd` 写 0 是为了与
   `duck-control` 的 `set_gain` 对齐——robotd 接管后会用 `robotd.toml` 的 `gain`
   覆盖 RAM 50，所以**两边要一致**，见下面《真机实测》。
8. **初始位置校准**（按下面选的方式）。
9. **打开写入锁**（55 号写 1，EPROM 掉电不保存），再回读 ID / 波特率 / 锁 / 模式 /
   角度限制（按上面的选择校验单圈 0/4095 或多圈 0/0）/ **19 号卸载条件** /
   位置偏移 / 15 字节反馈做校验。
10. 结束时关闭扭矩，并提示断电、拔下、换下一颗。

写入锁的措辞容易记反，按厂商内存表的字面意思：**写 0 = 关闭写入锁**（能改 ID/波特率，
掉电保存），**写 1 = 打开写入锁**（掉电不保存）。所以“解锁”是写 0，“上锁”是写 1。

#### 还有一条：56 号位置读数必须在单圈 0..4095 里（2026-10-05 加）

出厂 **18 号相位 = 0x34**（bit 4「角度反馈模式 = 全角度」，15 个舵机完全一致，真机实测）
时，位置读数**不会自己回绕**：关节被手推过一整圈之后 56 号会读到 4096 以上。`robotd`
的驱动层只读单圈字段（`bus.rs` 的注释写着 "masks around rather than solves"），超出的
读数被取模屏蔽——于是"目标 == 实测"看着一切正常，其实差着一整圈，**下一次写目标就把
关节转回去一整圈**。2026-10-05 真机：`head_yaw` 读到 **6289**，`robotctl robot init`
时脖子飞快转了两圈，并且把相邻的 `head_roll` 顶进了过流错误（status `0x08`），
连 `robotctl robot relax` 都写不进去（"cannot cut torque"）。

初始化流程现在会**检查并修复**这一条：按**整圈挪 31 号位置偏移**把读数搬回窗口。
关节角是 `方向 · ((位置 mod 4096) − 2048)`，整圈平移对它不变，所以**物理姿态一动不动**；
只有整圈平移会超出偏移量程（±4095）时才失败，让人先把关节转回来。
**工具不在这里动相位**：全角度反馈是这批舵机的出厂约定，改它等于改整机的反馈表示；
真正需要改的是"读数跑出单圈之后没人管"这件事。

### 15 台列表的读法（点检 15 台 / 检测总线）

列表按 **ID 升序**排列（`10~14 / 20~24 / 30~34`），点一次 **点检 15 台** 或 **检测总线**
就逐个 PING 全部 15 个关节，把结果画成三种状态：

| 显示 | 含义 |
|---|---|
| 黄色（●） | 该 ID 在总线上**有应答**（来自 `census` / `precheck` 的 `present_joints`） |
| 绿色（✔） | **本页向导已经完成**过这个关节的初始化/校准（进度标记） |
| 灰色（序号） | 还没点检过，或无应答 |

列表与「下一个关节」的推进顺序都是 ID 升序；接口 `/api/joints` 本身仍按
`model.rs` 的 `JOINT_IDS` 顺序（左腿→头颈→右腿）返回，界面只改显示顺序。

点检结果表会同时列出每个在线舵机的**多圈状态**与 **19 号卸载条件**（含打开的保护位名），
方便装配前一眼看出哪台舵机的零位/保护配置与预期不同。点检是**完整点名**：
本次没有应答的关节会被清成灰色，不会留下上一次的黄点。

### 04 页「中位校准（CAL）」的保存选项

CAL 把**此刻的物理位置**写成单圈中点 **2048 计数（180°）**，并改写 **31 号位置偏移**
（EPROM 字段）。写入锁打开（55 号 = 1）时 EPROM 写入**掉电不保存**，所以厂商的
`CalibrationOfs()` 必须先解锁（55 号 = 0）再 CAL——这一步是必要的，不是可选项。

区别只在于 CAL 之后要不要补一次上锁，界面上就是那个默认勾选的
**「保存到 EPROM 并重新上锁」**：

| 勾选 | 实际动作 | 什么时候用 |
|---|---|---|
| **勾选（默认）** | 解锁 → CAL → **55 号写回 1** | 常规：校准结果已经写完并保存，上锁只是恢复到“EPROM 掉电不保存”的保护状态，不留一颗没上锁的舵机 |
| 取消勾选 | 解锁 → CAL（**保持解锁**） | 连续做多次 CAL / 偏移调试时，省掉每次重新解锁 |

两种情况下**校准结果本身都已经掉电保存**（因为 CAL 是在解锁状态下写的）；
上锁发生在写完之后，不会撤销这次校准。

### 位置环增益：为什么初始化要写它（真机实测）

`robotd` 启动时会按 `robotd.toml` 的 `gain` 把 **RAM 50（Kp）** 覆盖成它自己的值
（`duck-control/src/bus.rs` 的 `set_gain`），而那份配置的默认值 `gain = 200` 是给
Dynamixel XL330 的 **0..16383** 标度调的——在飞特的 **0..254** 上就是顶格。

| RAM 50（Kp） | left_hip_yaw（ID 20）实测 |
|---|---|
| 200 | 自激振荡：峰值电流 4966–5388 mA、目标不动时自报速度 4.37 rad/s、壳温升到 **74 °C** 且持续上升、人耳听到剧烈抖动 |
| **32**（厂商默认） | 峰值 110 mA、平均 20 mA、速度峰值 0.307 rad/s、通电 6 s 温度不变（48→49 °C） |

同一只鸭子、同一份固件、只改这一个数值；其余 14 台在两种增益下电流都接近 0。
所以初始化默认写 32/0，并且**两处都写**（EEPROM 让舵机自己上电时是对的，
RAM 让它不必等下一次上电）。注意这只是台面结论：真正的稳定裕度要按关节在负载下整定。

### 四种初始位置校准方式

| 方式 | 做什么 | 用在哪 |
|---|---|---|
| 中位校准（CAL） | 执行厂商 `CAL(0x0B)`，把**此刻的物理位置**写成 **2048 计数** = 关节角 0，并改写 31 号位置偏移 | 想让所有舵机有一个统一的机械基准时；语义确定、实测可复现。15 台现在就是这个状态 |
| 按 home 姿态写位置偏移 | 把 31 号位置偏移改成「此刻读数 = 该关节 home 姿态角」，目标计数 = **2048 + 方向 × home 角计数**（left_hip_pitch → **2347**） | 整机对齐 `DEFAULT_POSITION`；工具按**正反两种约定**各有界搜索候选偏移、逐个回读验证（见上文实测 3），全不中就把原偏移写回并报失败 |
| 转到中位（2048） | 写目标位置 **2048**（关节角 0、一圈中点），到位后保持扭矩，便于按舵盘标记装配（不写 EPROM） | 推荐：装舵盘时把机械零位定好，31 号偏移保持 0。注意不是写 0——0 是一圈的另一端（≈ −180°） |
| 不校准，只改 ID | 只写 ID/波特率，零位由机械装配决定 | 装好之后再整体校准 |

“重新初始化”模式（界面上可切换）把源 ID 从出厂 ID 1 改成目标 ID 本身，
用于重新编号或**重新校准一颗已经编过号的舵机**；这个模式下不会改写主 ID。

### 真机实测（三条结论，按重要性排列）

在 HD-1910-C001（固件 3.46）上实测。

**1. 出厂设置下负的目标位置不生效——但整机现在不需要负值。**

| 9 号 / 11 号角度限制 | 写目标 −500 | 42 号（目标）回读 | 56 号（当前） | 67 号（目标回读） |
|---|---|---|---|---|
| 0 / **4095**（出厂） | 被接受 | `−500` (0x81F4) | **`0`，舵机没动** | **`0`** |
| 0 / **0**（多圈） | 被接受 | `−500` (0x81F4) | **`−500`** | **`−500`** |

协议层一直「接受」负值（42 号回读就是 −500），但 11 号 = 4095 把位置坐标夹在一圈
`[0, 4095]` 内，负目标被夹到 0。厂商内存表在 9/11 号上写的「多圈绝对位置控制时此值为 0」
就是开关，实测有效。

> **2026-10-05：这条对整机的结论已经反过来，别照旧读。** 关节表里有 4 个 home 姿态角是负的，
> 但工具写下去的**从来不是负值**：单圈 + 「零点 2048、方向 −1」这套坐标把负角表示成 2048
> **以上**的计数（left_hip_pitch −299 → 2347），所以单圈就够了，**不需要**为这 4 个关节
> 打开多圈。现在整机按单圈跑（`robotd` 的审计也要求 9/11 = 0/4095），界面上的开关默认关闭
> 就是整机配置；打开它只在台面上要转到一圈以外、或要写有符号绝对值时才用。

**2. 推荐配置：多圈打开 + 位置偏移保持 0，零位由机械装配决定。**

打开多圈、31 号偏移为 0 时坐标是干净的，负目标精确跟随：

| 写目标 | 当前位置 | 67 号目标回读 |
|---|---|---|
| 0 | 0 | 0 |
| −500 | **−500** | **−500** |
| −1000 | **−999** | **−1000** |
| −300 | **−301** | **−300** |

也就是说：把舵盘装在 home 姿态、让 home 姿态的读数落在目标附近，然后把 31 号偏移
留给「小幅修正」——这条路径实测最稳。代价是固件不再限制行程，行程要靠 `robotd` 兜住。

**3. 拿大偏移去搬原点：那条"重锚"其实可以复算成取模回绕。**

写一个较大的偏移会让固件把编码器坐标**重锚**：实测偏移 −3591→−3091（+500）后读数从
−4096 变成 −500（差 3596），而 −3591→−4591（−1000）后读数从 −4096 变成 −3096（差 1000）
——同一根轴，写偏移前后的差值不是同一个常量；读数还总被折进约 ±2 圈的窗口。
手册没写这些（`docs/飞特通讯协议说明.md` 第 12.5 节把它列为未确认项）。

> **2026-10-05 复算：那四个点其实都满足 `位置 + 偏移 = −7687`（常数）**，也就是
> `位置 = 编码器 − 偏移` 的线性关系成立，"差值不是常量"是因为读数被折进窗口后再读出来的
> 是**回绕值**（−4596 读成 −500 之类）。所以严格说不是"重锚"，而是"显示窗口取模"。
> 这条目前只是**事后复算**，还没有按公式在真机上写过；等实测确认后再把下面的有界搜索
> 换成一次公式写入。在那之前维持原样。

所以「按 home 姿态写位置偏移」这个校准**不做公式假设**：有界搜索候选偏移（正反两种约定
都试）、逐个回读验证，只有落进 8 计数（≈0.70°）容差才算成功；全都不中就把原偏移**写回去**
并报失败。经验规律是**所需偏移越小越可靠**，所以校准前让读数落在 0 附近最省事
（舵盘换个齿位即可）。

另外两条实测结论：

- **CAL 的「中点」是 2048 计数（180°），不是 0**：CAL 前 偏移 = 0、位置 = 72；
  CAL 后 偏移 = −1976、位置 = 2048。
- 一圈内模式下位置被夹在一圈内，负结果回绕成 `4096 + 值`
  （偏移扫一圈时 −98 → 3999、−498 → 3599、−1998 → 2099）。
- **19 号「卸载条件」出厂只开过热保护**：2026-10-03 在 16 台 HD-1910-C001
  （固件 3.46）上逐台回读，`19 = 4 (0x04)`，即 BIT2 过热保护打开、BIT0 电压、
  BIT1 磁编码、BIT3 过流都**没有**打开。工具的「只按读改写动 BIT0/BIT3」就是按这个
  事实设计的：勾选/取消电压或过流时，BIT1/BIT2 保持原值（真机验证：`4 → 13 → 4`，
  BIT2 全程为 1）。

对 `microduck` 的影响：`duck-control/src/feetech.rs` 的 `position_rad()` 按「BIT15 为方向位」
解读位置字段，与 `DEFAULT_POSITION` 的负角一致；打开多圈后舵机给的正是这种写法。
仍然建议上整机前以 `robotd` 侧读到的关节角复测一次。

校准只改坐标原点，不校验机械姿态：勾选「已把该关节摆到基准位」只是确认你摆好了。
想恢复出厂零位，把 31 号位置偏移写回 0；想恢复一圈行程，把 11 号写回 4095。

### 安全须知

- **一次只接一个新舵机**：两颗出厂 ID 都是 1 的舵机同时在线时会被一起改名，
  产生重复 ID，之后整条总线的读写都会互相打架。
- 初始化会写 EPROM，并且 CAL / 转到位置 0 会让舵机转动，请先确认机械安全、可以随时断电。
- 用 CAL 或位置偏移校准前，先确认这颗舵机确实处在它该在的基准位。
- **电压 / 过流保护（19 号）默认不打开**：它们触发时舵机会卸载（不再输出扭矩），
  对一条腿站着的机器人等于摔倒。要在整机上打开就明确知道自己在换什么。
- 想恢复出厂零位，把 31 号位置偏移写回 0 并重新上电即可。

## 故障排查

- **爆出“打开串口失败”**：检查设备名、USB 线、供电、`dialout` 权限。
- **一直等待应答超时**：优先检查波特率是否匹配；HLS 默认 1 Mbps。
- **Ping 收到但读写失败**：确认 ID 是否为总线地址/副 ID；确认目标设备不是只响应主 ID。
- **写 EPROM 不保存**：写 55 号锁标志为 0（关闭写入锁）后再写，然后重新上电验证。
- **修改 ID/波特率后连不上**：换用新 ID/新波特率重新连接。
- **同步写没反应**：SYNC_WRITE 是广播，没有应答；先确认舵机处于正确模式，且每个 ID 的数据长度一致。
- **位置角度不对**：按 4096 计数/圈换算，且**零点在 2048、方向是 −1**
  （`关节角 = −(计数 − 2048) · 0.0879°`）。扭矩关掉后位置可能可以手动转动，这是正常现象。
- **负角关节不进反方向 / 写负位置舵机不动**：出厂 11 号最大角度限制 = 4095 把行程
  锁在一圈内，**负数**目标会被夹到 0。整机现在不需要负值——单圈 + 「零点 2048、方向 −1」
  把负的关节角表示成 2048 以上的计数（left_hip_pitch −299 → 2347），所以保持单圈即可。
  只有台面上要转到一圈以外时才用「舵机初始化」页签勾上「打开多圈绝对位置控制」，
  或手动把 9 号与 11 号都写 0。实测对照见上文《真机实测》。
- **位置偏移校准报「没能把读数调到…已把位置偏移恢复为…」**：说明当前读数离目标
  太远。把关节摆到更接近 home 的位置，或把舵盘换个齿位让读数落在目标附近再校准；
  工具已经把偏移恢复成原值，不会留半校准状态。
- **初始化说“ID 1 没有应答”**：确认只接了新舵机、已上电、波特率是 1 Mbps；
  用“连接与扫描”里的“自动探测 ID1”或全总线扫描确认它到底在不在。
- **初始化说“目标 ID 已经在应答”**：这个关节已经编过号了。要么换一颗新舵机，
  要么把界面上的模式切到“重新初始化”。
- **初始化说“目标 ID 是 20 却报 ID 是别的”**：多半是总线上有重复 ID，
  或者目标 ID 的舵机不是你以为的那一颗。先用“点检 15 台”看清楚谁在线。
- **CAL 之后读数是 2048**：这是正确的——**2048 就是关节角 0**，与 robotd 的驱动层一致，
  不是旧文档里说的“180° 中点所以不对”。想看 home 姿态该读多少，用上表的「舵机字段」列
  （left_hip_pitch 是 **2347**）。
- **负角关节的偏移校准目标是多少**：`2048 + 方向 × home 角计数`。`left_hip_pitch` 的 home 角
  是 −299 计数、方向 −1，所以目标是 **2347**（不是 −299，也不是 1749——1749 是**镜像**位置）。
  界面上会直接把目标数打出来。
- **我照着一张写着 1749 的表把关节摆过去了**：那张表是 2026-10-03 方向翻转之前的，
  整列镜像。正确值见上表；摆错的后果是 15 个关节全部对到镜像位置（`robotctl monitor`
  会显示每个关节读 π 附近或明显反向）。
- **明明取消了多圈、9/11 号却还是 0/0**：这是旧版的行为（取消勾选只是“跳过不写”）。
  现在两个方向都会真的写寄存器，取消勾选就把 9/11 号写成 0/4095；如果回读仍不是，
  看结果框里的「关闭多圈，恢复单圈行程」那一步回读值是多少。
- **点检后黄点/绿点不对**：黄点来自最近一次「点检 15 台」或「检测总线」的完整点名，
  绿点是**本页**的完成标记（刷新页面会清掉），两者都不代表舵机的零点真的校好了。
- **扫描少发现舵机（已修）**：早期扫描范围默认只到 ID 20，把 ID>20 的舵机整段漏掉
  （实测 10~14、20、21 共七台只报 6 台，漏的正是 21）。现已把界面、`/api/scan`、
  `HLSBus.scan()` 的默认上限全部改为 **253**，默认全总线扫描约 12 秒。
  注意扫描区间是**闭区间**：结束 ID 必须 ≥ 最大舵机 ID。
- **写运行模式 4 被拒绝（已修）**：`HLSBus.set_mode()` 原先按手册的 `0~3` 校验，
  但本机型出厂就是模式 4（与模式 0 同属位置环），界面上的“位置 (4)”按钮因此会报错。
  现已放开到 `0~4`。

## 安全提示

调试软件可以通过浏览器直接驱动舵机。所有写入都会立即发送到总线，
请务必：
- 固定好机械结构，避免堵转、飞车或夹伤；
- 初次使用低速度、低加速度、低电流；
- 随时准备断开舵机电源；
- **注意：写目标位置会自动打开扭矩**（实测本固件行为），所以"关闭扭矩"后
  再写位置会重新带电；需要卸力时请在最后一次位置写入之后再点"关闭扭矩"。
  这一条对机器人软件同样成立，而且是 `robotctl robot relax` 曾经"卸不了力"的原因：
  控制环每个 tick 都会写目标位置，于是卸力只维持了不到 20 ms。修法见
  `microduck_feetech/FORK.md` 的「`robot relax` 卸不了力」一节与
  `duck-control/src/safety.rs` 的 `Safety::powered`；
- 不要把 `RESET`、`CAL`、改 ID/波特率等操作当成常规测试按钮反复点击；
- 整机初始化会写 EPROM，而且 CAL / 转到位置 0 会让舵机动起来；
  **一次只接一个新舵机**，否则两颗出厂 ID 1 的舵机会被一起改名，产生重复 ID；
- 重复 ID 会让总线上所有读写互相打架，且症状像接线故障，接线时务必一颗一颗来。

## 无硬件自检

不连接舵机也可以运行协议自检，验证帧构造、校验和、串口读取状态机、
同步读解析、内存表编解码、反馈解码，以及用一个从站模拟跑完整套
“出厂 ID 1 → 关节 ID + 校准”的初始化流程：

```bash
uv python -m hls_debugger.selftest
```

## 真机连通性测试

`hw_test.py` 用真实串口完成只读验证（只发 PING 和 READ，不发任何运动指令）：

```bash
uv python hw_test.py --port /dev/ttyACM1
```

它会打印设备信息、各波特率下的 ID 扫描、版本/ID/波特率/模式/扭矩/写锁，
以及 56~70 号 15 字节实时反馈的完整解码。若首个波特率无应答，会自动遍历
`1000000 / 115200 / 500000 / 250000 / 128000 / 76800 / 57600 / 38400`。


### 现场注意

- 波特率索引 0 = 1 Mbps，与本工具默认一致；改波特率后需按新速率重连。
- 锁标志为 1 时写 EPROM 掉电不保存，**改 ID/波特率等需先解写锁（55 号写 0）**。
- 位置偏移会把读数整体平移，且按一圈取模；负值有时报负、有时回绕，属实测现象。
  校准请用“舵机初始化”页签，它按一圈取模比较、留容差并回读校验。

## 实机操作记录（供复现参考）

以下步骤在本工具上对真机跑通过，可作为复现脚本的参照：

1. 接上出厂新舵机到 `/dev/ttyACM0`，连接后 `POST /api/provision/precheck {"id":20,"mode":"fresh"}`：
   `source_present=true`、`target_present=false`。
2. `POST /api/provision {"id":20,"mode":"fresh","calibrate":"cal"}`：
   ID 1 → 20，波特率 0，应答级别 1，CAL 把位置 72 写到 2048，上锁，状态 0。
3. `POST /api/provision {"id":20,"mode":"reinit","calibrate":"mid","speed":80,"acc":20}`：
   输出轴从 2048 转到 0（误差 2 计数 ≈ 0.18°），扭矩保持开启。
4. `POST /api/provision {"id":20,"mode":"reinit","calibrate":"offset"}`：
   位置偏移 3000 → 2121，读数 3217 → 0，校验通过。
5. `POST /api/provision/census`：应报出全部已编号的关节，未编号的位置显示“—”。

### 2026-10-03：本轮改动的真机验证（`/dev/ttyACM0`，16 台在线）

总线上是 16 台 HD-1910-C001（固件 3.46 / 舵机 10.31）：ID `1, 10~14, 20~24, 30~34`，
1 Mbps。测试**全部可逆**，结束前逐项写回，收尾用同一份只读盘点与测试前逐字节比对。

| 整流程 `provision(mode=reinit)` | 对在线关节 ID 20 跑完 14 个步骤全部 OK，含“关闭多圈，恢复单圈行程”与

点检 15 台会因此多 15 次单字节读——实测 15 台总耗时仍在 1~3 秒量级。
