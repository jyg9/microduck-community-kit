# 飞特（FeeTech / Feetech）SCS·HLS 串行总线协议说明

本文件是 `imu_to_dxl` 节点（`firmware/v1`）复刻飞特舵机总线所依据的协议说明，
内容逐条来自本目录下的官方参考实现，并标注了不确定项。

**资料来源（本目录内，可直接核对）**

| 来源 | 路径 | 用途 |
|---|---|---|
| 飞特 Linux C++ 参考库 | `FTServo_Linux-main/src/SCS.cpp`、`SCS.h`、`SCSeriaI.cpp`、`INST.h` | 帧格式、校验和、指令集、超时/ACK 语义 |
| 飞特 HLS 系列应用层 | `FTServo_Linux-main/src/HLSCL.cpp`、`HLSCL.h` | 内存表地址、位置/速度/电流等读写方法 |
| 飞特 STM32 HAL 参考库 | `FTServo_stm32HAL-main/SCSLib/` | 同一协议的 MCU 端实现（用于交叉验证） |
| 官方例程 | `FTServo_Linux-main/examples/HLSCL/` | Ping / Read / Write / SyncRead / SyncWrite 用法 |
| 飞特官网内存表入口 | `HLS系列舵机内存表.html`（门户页） | 具体型号的完整内存表需在该站点按型号下载 |

> 与 Dynamixel 的关系：飞特 SCS/HLS 是**另一套**协议，帧头同为 `0xFF 0xFF`，但之后是
> `ID LEN INST ...` + **8 位取反校验和**，而 Dynamixel 2.0 是 `FD 00 ID LEN_L LEN_H INST ...`
> + **CRC-16**。两者可以在同一条半双工串口总线上共存，见第 9 节的自适应判据。

## 1. 物理层与链路特性

| 项目 | 说明 |
|---|---|
| 总线 | 单线半双工（收发共线），所有节点并联；任意时刻只能有一个发送方 |
| 电平 | TTL 3.3 V（配合总线缓冲/方向控制电路，如 `elec_imu_to_dxl` 中的自动方向电路） |
| 数据格式 | 8N1（8 数据位、无校验、1 停止位），无流控 |
| 波特率 | 由寄存器 `BAUD_RATE`(6) 选择，见第 8 节编码表；上电默认波特率以型号手册为准 |
| 应答 | **每条指令都由目标节点回一帧应答**（参考库 `Level=1` 时 `Ack()` 总是等待），因此飞特总线**没有 Dynamixel 那种 `return_delay_time` 轮流应答延迟** |
| 广播 | ID `0xFE` 用于 `SYNC_READ` / `SYNC_WRITE`；同步写不产生任何应答 |
| ID 范围 | 0~253，出厂默认 1（`0xFD` 与 Dynamixel 2.0 的帧头字节冲突，见第 7 节） |
| 应答级别 | 寄存器 8（`应答状态级别`）：0 = 除读/PING 外不应答，1 = 全部应答；出厂默认 1 |
| 写入锁 | 寄存器 55（`锁标志`）：控制 EPROM 写入是否掉电保存，不是禁止写入；出厂默认 1 |

参考库的 ACK 行为（`SCS::Ack`）：主机发出指令后等待 `FF FF ID LEN STATUS ~SUM`，
校验 `ID` 与 `LEN==2`，再比较校验和；任一步失败返回 `u8Error`（`INST.h`）：

```
ERR_NO_REPLY = 1   无应答/超时
ERR_CRC_CMP  = 2   校验和错误
ERR_SLAVE_ID = 3   应答 ID 不是目标 ID
ERR_BUFF_LEN = 4   长度字段错误
```
这 4 个是**主机侧**错误码（参考库内部使用），不是总线上传输的字节。

## 2. 帧格式

### 2.1 指令帧（主机 → 节点）

```
偏移  0     1     2    3    4      5        6..        末字节
     FF    FF    ID   LEN  INST   ADDR     DATA...     ~SUM
```

* `LEN` 统计 **INST + ADDR + DATA + SUM** 的字节数（即 `LEN = 数据长度 + 3`，无数据时为 2）。
* 整帧长度 = `LEN + 4`（2 个帧头 + ID + LEN + LEN 个字节）。
* 校验和：`SUM = ID + LEN + INST + ADDR + ΣDATA`，发送的是 `~SUM`（按位取反，保留低 8 位）。
  **当指令不带 ADDR 时（PING / REG_ACTION / RESET / CAL），ADDR 按 0 参与校验和**，
  这一点参考库 `SCS::writeBuf()` 写得很明确：`CheckSum = ID + msgLen + Fun + MemAddr;`
  其中 `MemAddr` 形参在这些调用里传 0，而帧里并不出现该字节。
* 多字节数据默认**小端**（`SCS(End=0)`；`Host2SCS()` 在 `End=0` 时先写低字节）。

### 2.2 应答帧（节点 → 主机）

```
偏移  0     1     2    3         4       5..       末字节
     FF    FF    ID   LEN     STATUS   DATA...     ~SUM
```

* `LEN = 数据长度 + 2`（STATUS + DATA + SUM），整帧长度 = `LEN + 4`。
* 校验和范围同指令帧：从 ID 到最后一个数据字节。
* `STATUS` 正常为 `0x00`。**飞特公开资料没有给出舵机在异常时填什么**，
  参考库也从不检查它（只把 `u8Status` 存下来）。本项目的节点使用自定义约定，
  见第 10.3 节。

### 2.3 逐字节示例（用本项目的节点 ID=200=0xC8 计算）

| 帧 | 字节 | 说明 |
|---|---|---|
| PING 指令 | `FF FF C8 02 01 34` | `LEN=2`，`SUM=C8+02+01=CB`，`~CB=34` |
| PING 应答 | `FF FF C8 02 00 35` | `SUM=C8+02+00=CA`，`~CA=35` |
| READ(地址 56, 长度 12) | `FF FF C8 04 02 38 0C ED` | `SUM=C8+04+02+38+0C=112→12`，`~12=ED` |
| READ 应答（12 字节数据 D0..D11） | `FF FF C8 0E 00 D0..D11 ~SUM` | `LEN=12+2=0x0E` |
| WRITE(地址 5, 值 42) | `FF FF C8 04 03 05 2A ~SUM` | `SUM=C8+04+03+05+2A=FE`，`~FE=01` |

（这些向量在 `firmware/v1/host/bus.py` 的 `_self_test()` 与
`v1/host/tools/test_protocols.c` 中都有断言，可与固件实现逐字节对齐。）

## 3. 指令集

`INST.h` 中的定义与参考库实现一一对应：

| INST | 名称 | 参数 | 应答 | 说明 |
|---|---|---|---|---|
| `0x01` | PING | 无 | `FF FF ID 02 STATUS ~SUM` | 查询节点是否在线；广播 ID 时所有节点应答 |
| `0x02` | READ | `ADDR`, `nLen` | STATUS + nLen 字节数据 | 读内存表 |
| `0x03` | WRITE | `ADDR`, `DATA...` | STATUS | 立即写 |
| `0x04` | REG_WRITE | `ADDR`, `DATA...` | STATUS | 暂存写，等待 `REG_ACTION` 生效 |
| `0x05` | REG_ACTION | 无 | STATUS | 执行所有暂存写 |
| `0x06` | RECOVERY | 无 | STATUS | 参考库定义（用于从保护状态恢复） |
| `0x08` | **REBOOT** | 无 | **无应答** | 重启舵机，约 800 ms 后回来；手册要求**先关闭扭矩**。**本表原先漏了这一条**（依据的是更旧的手册），2026-09-24 在真机 HD-1910-C001（fw 3.46）上实测确认：见第 13 节 |
| `0x09` | 参数备份 | 无 | STATUS | 备份当前参数（较新手册；本节点不实现） |
| `0x82` | SYNC_READ | `ADDR`, `nLen`, `ID...` | 每个被点名节点各回一帧 | 一次广播读取多个节点，见第 4 节 |
| `0x83` | SYNC_WRITE | `ADDR`, `nLen`, `ID, DATA...` | **无应答** | 一次广播写入多个节点 |
| `0x0A` | RESET | 无 | STATUS | 恢复出厂设置 |
| `0x0B` | CAL | 无 | STATUS | 中位校准（`CAL`，写入 `OFS`） |

## 4. 同步读 / 同步写

### 4.1 SYNC_READ（0x82）

请求（`SCS::syncReadPacketTx`）：

```
FF FF FE LEN 82 ADDR nLen ID0 ID1 ... IDn-1 ~SUM
LEN = IDN + 4
SUM = 0xFE + LEN + 0x82 + ADDR + nLen + ΣID
```

* 每个被点名的节点都按**普通应答帧**回答自己的数据：`FF FF ID (nLen+2) STATUS DATA... ~SUM`。
* 主机需要按 `ID` 顺序收集（参考库 `syncReadPacketRx` 用固定缓冲逐帧扫描 `FF FF`，
  并校验 `LEN==nLen+2` 与校验和）。
* **应答顺序由各节点自行决定**（总线上是竞争关系）；参考库靠遍历缓冲区分帧，
  因此主机必须允许乱序到达。

### 4.2 SYNC_WRITE（0x83）

```
FF FF FE LEN 83 ADDR nLen ID0 D0... ID1 D1... ~SUM
LEN = (nLen + 1) * IDN + 4
SUM = 0xFE + LEN + 0x83 + ADDR + nLen + Σ(ID_k + DATA_k)
```

写入的数据块长度对所有节点必须一致；**不产生任何应答**（连 STATUS 都没有）。

## 7. ID 与帧头的冲突

* 飞特 ID 允许 0~253，其中 `0xFE` 保留为广播；`0xFD` 理论上可作 ID，
  但 `0xFD` 是 **Dynamixel 2.0 帧头的第 3 字节**（`FF FF FD 00`）。
* 两种协议共存时，接收方用"第 3 字节是否为 0xFD"来区分协议，
  因此**本项目的节点禁止使用 ID=0xFD**（固件解析器直接丢弃第 3 字节为 `0xFD` 的飞特帧，
  配置写入时把 ID 限制在 0~252）。

## 8. 波特率编码

> ⚠️ **HLS 系列手册给出的寄存器 6 量程是 0~7**（到 38400 为止）；
> 参考库 `INST.h` 里多出的 8~11（19200/14400/9600/4800）属于其它系列，HLS 上写这些值的行为
> 未在手册中定义。

| 编码 | 波特率 | 编码 | 波特率 |
|---|---|---|---|
| 0 | 1 Mbps | 6 | 57600 |
| 1 | 500 kbps | 7 | 38400 |
| 2 | 250 kbps | 8 | 19200 |
| 3 | 128 kbps | 9 | 14400 |
| 4 | 115200 | 10 | 9600 |
| 5 | 76800 | 11 | 4800 |

注意与 Dynamixel 的波特率寄存器编码**完全不同**（Dynamixel：`3` = 1 Mbps）。

## 9. 与 Dynamixel 2.0 共存时的自适应判据

| 帧的第 3 字节 | 判定 |
|---|---|
| `0xFD` | Dynamixel 2.0（后随保留字节 `0x00`、ID、LEN_L、LEN_H…） |
| 其它 | 飞特 SCS/HLS（后随 `LEN`，要求 `LEN >= 2`） |

主机（PC 上位机 / `robotd`）**自己选择**发哪种协议；节点侧不需要配置。
为避免把某帧数据里的 `FF FF <本机 ID>` 误判成飞特帧，本项目固件在成功应答一种协议后
会在 1 秒内"粘"在该协议上（`BUS_PROTO_STICKY_MS`），并提供
`proto_lock`（0=自动 / 1=Dynamixel / 2=飞特）强制锁定。

## 10. 本项目的 `imu_to_dxl` 节点在飞特协议下的映射

固件文件：`firmware/v1/src/fee.c`（协议）、`src/dev.c`（内存表镜像）。

### 10.1 节点身份

| 项目 | 地址 | 值 |
|---|---|---|
| 型号 | 3 / 4 | `0x0C00`（自定义，小端；用于把本节点与飞特舵机区分开） |
| ID | 5 | 默认 200（可写并持久化；禁止 >252） |
| 波特率 | 6 | 默认 0（1 Mbps） |
| 第二 ID | 7 | 254（关闭） |
| 工作模式 | 33 | 0（本节点不运动） |
| 扭力 | 40 | 可写，无实际作用（保持"像舵机"以便工具链扫描） |

### 10.2 遥测块（关键设计）

IMU 遥测块是 **20 字节**，被**别名**到飞特内存表的状态区：

| 地址 | 内容 |
|---|---|
| 56~75 | 20 字节遥测块（50 号位置起，覆盖 `PRESENT_POSITION`~`PRESENT_CURRENT`） |
| 128~147 | 同一份 20 字节遥测块的干净副本（厂商窗口） |

也就是说：对一次 `SYNC_READ(56, 12, [IMU_ID, 舵机ID...])`，
舵机在自己的 56 地址返回位置/速度/负载等状态，本节点在同一地址返回**前 12 字节 IMU 块**，
主机用同一事务即可同时拿到姿态与全部关节状态——这正是 Dynamixel 侧
"IMU 与舵机共用地址 124 一次 sync_read"的设计在飞特侧的等价物。

块的字节布局（两种协议完全一致，见 `src/imu.h`）：

| 字节 | 内容 |
|---|---|
| 0~5 | 陀螺 x/y/z，i16 小端，±500 dps，17.5 mdps/LSB |
| 6~11 | 四元数 x/y/z，IEEE half（binary16），`w = √(1-x²-y²-z²)` |
| 12~17 | 加速度 x/y/z，i16 小端，±4 g，0.122 mg/LSB |
| 18 | 采样计数（u8，回绕） |
| 19 | 状态位：`0x01` SFLP 有效 / `0x02` 计数回绕 / `0x04` 陀螺饱和 / `0x08` 传感器错误 / `0x10` 模拟数据 / `0x20` 冻结模式 / `0x40` 配置未保存 / `0x80` 融合已收敛 |

主机必须**只取前 12 字节**才能与 `robotd` 现有解析保持一致。

### 10.3 厂商配置窗口（20 字节，地址 160~179）

与 Dynamixel 侧地址 148~167 是同一张表（偏移相同），见
`firmware/v1/src/board.h` 的 `V_*` 常量：

| 偏移 | 名称 | 说明 |
|---|---|---|
| 0~1 | `MAGIC` | `0x4D49`（'I','M' 小端）；写入时用于判断窗口是否有效 |
| 2 | `CMD` | 命令：1=保存配置到 Flash，2=恢复出厂，3=重启，4=重启运动模型；执行后自动清 0 |
| 3 | `SIM_MODE` | 模拟模式：0 静止 / 1 正弦 / 2 漂移 / 3 噪声 / 4 自转 / 5 SFLP 未就绪 / 6 冻结 |
| 4~5 | `SIM_AMP` | 幅度千分比（100~5000） |
| 6~7 | `SIM_FREQ` | 频率千分比（100~5000） |
| 8 | `REPORT_FRAME` | 0=芯片坐标系（与真板一致，默认）/ 1=躯干系（调试方便） |
| 9 | `PROTO_LOCK` | 0=自动 / 1=仅 Dynamixel / 2=仅飞特 |
| 10~15 | `GYRO_BIAS_X/Y/Z` | i16，直接叠加到上报的陀螺原始计数上（用于注入偏移/做在线标定） |
| 16 | `MIRROR_BAUD` | 调试/镜像口波特率编码（飞特编码表） |
| 17 | `DBG_LEVEL` | 0 关闭 / 1 仅错误 / 2 启动+周期统计 / 3 每帧跟踪 |
| 18 | `STATUS` | 只读：bit0 配置未保存 / bit1 配置来自 Flash / bit2 使用模拟数据 |
| 19 | 保留 | |

### 10.3.1 与手册对齐的设备语义

本节点实现了手册里的两个关键寄存器语义（有上板回归）：

| 寄存器 | 手册语义 | 本节点 |
|---|---|---|
| 8 应答状态级别 | 初始值 1；0 = 除读/PING 外不应答，1 = 全部应答 | 一致：默认 1，写 0 后写指令执行但静默，读指令仍应答 |
| 55 锁标志 | 写 0 = EPROM 写入掉电保存；写 1 = 掉电不保存（**不是拒绝写入**） | 一致：加锁时写入仍进入 RAM 镜像，只是不标记为需要持久化；**默认值本节点取 0（手动册初始值为 1）**，这样主机改 ID/波特率后能直接存下来，属有意的偏差 |

另外本节点不实现：相位(18)/卸载条件(19)/LED 报警(20)/角度分辨率(30)/电流环(34/35)/
速度环(37/39)/出厂参数(77~86) 的执行语义（可读写，但不产生任何动作）。

### 10.4 本节点自定义的应答 STATUS

| 值 | 含义 |
|---|---|
| `0x00` | 成功 |
| `0x01` | 访问错误（写了只读区域） |
| `0x02` | 地址/长度越界 |
| `0x04` | 长度错误 |
| `0x08` | 其它错误 |

由于飞特未公开舵机的异常 STATUS 语义，以上取值是本项目的约定；主机只需判断是否为 0。

## 11. 主机侧实现建议

1. **校验和**：`(~(ID + LEN + INST + ADDR + ΣDATA)) & 0xFF`；注意无 ADDR 的指令按 0 计入。
2. **分帧**：不要假设应答按请求顺序到达；扫描缓冲里的 `FF FF`，用 `LEN` 与校验和双重确认。
3. **同步读缓冲**：预留 `IDN * (nLen + 6)` 字节（参考库 `syncReadBegin` 的大小），
   并把超时设置为"最慢节点"的往返时间。
4. **不要发 `0xFD` 作为 ID**（与 Dynamixel 2.0 帧头冲突）。
5. 与 Dynamixel 混用时，**每帧独立判协议**，但建议同一个会话内保持一种协议，
   避免两种协议的 CRC/校验失败计数互相污染。
6. Rust 侧（`microduck`）实现建议与补丁方案见
   `firmware/v1/patches/README.md`；
   Python 侧的参考实现见 `firmware/v1/host/bus.py`（`fee_*` 函数）。

## 12. 尚未确认的点（诚实清单）

1. **HD-1910-C001 专有值**：本文件的地址/单位来自 HLS 系列通用手册；
   该型号的 P/D 初始值、保护电流、最大速度等出厂参数需要该型号手册或实测确认。
2. **应答 STATUS 的异常语义**：手册只说明"舵机状态"在寄存器 65，
   没有定义应答帧里 STATUS 字节在异常时填什么。本节点使用自定义约定（见 §10.4），
   主机应只判断是否为 0。
3. **`RESET`(0x0A) 与 `RECOVERY`(0x06) 的完整行为**：手册未描述指令层细节，
   本节点把 RESET 实现为恢复出厂设置、RECOVERY 实现为应答 + 无动作。
4. **同步读的应答顺序**：手册未规定；参考库靠扫描缓冲区分帧，因此实现必须按 ID 匹配
   而不是按到达顺序（`microduck` 的飞特补丁即按此实现）。
5. **多圈模式与角度限制的交互**：手册说"多圈绝对位置控制时最小/最大角度限制为 0"，
   但多圈位置如何与 `OFS`(31) 组合未说明。**2026-09 已实测（见 §13.4）**：
   `位置 ≡ 编码器 − OFS (mod 4096)`；9/11 号写 0 之前负目标会被夹到 0，
   写 0 之后负目标生效。多圈下单圈以上的坐标表示仍未细测。

## 13. 真机实测补充（2026-09-24，HD-1910-C001，fw 3.46，1 Mbps）

### 13.1 `0x08` REBOOT（实测确认存在，本文件旧表漏列）

| 项 | 实测 |
|---|---|
| 指令 | `FF FF 01 02 08 <SUM>`（单播、无参数） |
| 应答 | **无**（主机侧 50 ms 超时，符合手册"不应答"） |
| 恢复时间 | **823 ms** 后 PING 恢复应答（手册/参考文档写"约 800 ms"） |
| ID / 波特率(6) / 模式(33) / 锁(55) / OFS(31) | **全部不变** |
| RAM 位置增益 50/51 | 先写入 99/88，重启后读回 **32/40**（= EEPROM 21/22）⇒ 重启把 RAM 增益重载为 EEPROM 值 |
| 扭矩(40) | 保持关闭（手册要求重启前先关扭矩） |

复现：`firmware/v1/host/tools/servo_reboot_probe.py --port /dev/ttyACM0`
（只写 RAM 增益 50/51 并还原，不动 EEPROM、不使能扭矩、不带载；ACM 编号以实际枚举为准）。

### 13.2 同步读的应答位次（实测线性 ≈295 µs/前导 ID）

`sync_read` 的 ID 列表里，每个排在目标设备**前面**的 ID（**即使那台设备缺席**）
会让它的首个应答字节推迟 ≈295 µs：一个前导 +0.302 ms、两个 +0.595、三个 +0.882
（各自 21 次取中位）。因此：

* "用总线静默 1 ms 判断前导设备缺席"这类启发式会晚一整槽；
* 自己实现从站时，应当按"每个前导 ID 占一个槽"让位（`firmware/v1/src/bus_arb.c`）；
* 反过来，**排在后面的设备只留给前一台 ≈295 µs**（21 字节应答 210 µs + 约 85 µs 空隙），
  这就是节点应答延迟的硬上限。

### 13.3 地址 56 的块长

真机对 `READ 56` 的 12 / 15 / **20** / 21 字节都正常应答；其中 **15 字节是文档化块**
（位置/速度/负载/电压/温度/状态/移动/电流），再往后 71..76 是别的寄存器。
所以"和舵机共用一次 `sync_read`"时读长应当取 15。

### 13.4 9/11 号角度限制、`OFS`(31) 与负位置（实测，补充 §12.5）

以 `software/hls_servo_debugger` 的初始化向导在 HD-1910-C001（fw 3.46）上测得。

**(1) 出厂设置下负的目标位置不生效——这一条最要紧：**

| 9 号 / 11 号角度限制 | 写目标 −500 | 42 号（目标）回读 | 56 号（当前） | 67 号（目标回读） |
|---|---|---|---|---|
| 0 / **4095**（出厂） | 被接受 | `−500` (0x81F4) | **`0`，舵机没动** | **`0`** |
| 0 / **0**（多圈） | 被接受 | `−500` (0x81F4) | **`−500`** | **`−500`** |

协议层一直"接受"负值（42 号回读就是 −500），但 11 号 = 4095 把位置坐标夹在一圈
`[0, 4095]` 内：负目标被夹到 0，舵机不往负方向走。手册在 9/11 号上写的
"多圈绝对位置控制时此值为 0"就是开关，实测有效。

**(2) 打开多圈、`OFS`(31) 保持 0 时坐标是干净的**——推荐配置：

| 写目标 | 56 号（当前） | 67 号（目标回读） |
|---|---|---|
| 0 | 0 | 0 |
| −500 | **−500** | **−500** |
| −1000 | **−999** | **−1000** |
| −300 | **−301** | **−300** |

即 `OFS = 0` 时读数就是编码器值；零位交给机械装配（把舵盘装在 home 姿态）。

**(3) 拿大偏移搬原点不可靠：写偏移会让固件重锚坐标。**

| 操作 | 偏移(31) | 位置(56) | 读数变化 |
|---|---|---|---|
| 起点 | −3591 | −4096 | — |
| 偏移 +500 | −3091 | −500 | +3596 |
| 偏移 +1000 | −2591 | −1000 | +3096 |
| 偏移 +2000 | −1591 | −2000 | +2096 |
| 偏移 −1000 | −4591 | −3096 | +1000 |

同一根轴、同一台舵机，写偏移前后的"读数变化 / 偏移变化"不是同一个常量，
读数还总被折进约 ±2 圈的窗口。因此**无法用 `OFS` 确定性地把读数钉在某个绝对值上**；
经验规律是"所需偏移越小越可靠"。一圈内模式还会把结果回绕成 `4096 + 值`
（偏移扫一圈时 −98 → 3999、−498 → 3599、−1998 → 2099）。

**(4) `CAL(0x0B)` 把此刻的物理位置写成 2048 计数（180°）**，不是 0，并相应改写 31 号偏移：
实测 CAL 前 偏移 = 0、位置 = 72；CAL 后 偏移 = −1976、位置 = 2048。

对 `microduck` 的影响：`duck-control/src/feetech.rs` 的 `position_rad()` 按"BIT15 为方向位"
解读位置字段，而 `DEFAULT_POSITION` 里有 4 个负角关节（left_hip_roll / left_hip_pitch /
left_knee / right_ankle）。**这 4 个关节要求 9/11 号必须为 0**，否则 `robotd` 发下去的
负目标会被固件夹到 0，关节停在 0 附近不动。打开多圈后固件不再限制行程，
关节限位要由 `robotd` 侧兜住；31 号偏移建议保持 0，零位由装配决定。

复现：`software/hls_servo_debugger` 的"舵机初始化"页签，
或 `POST /api/provision {"id":<关节ID>,"mode":"reinit","calibrate":"offset"}`。
